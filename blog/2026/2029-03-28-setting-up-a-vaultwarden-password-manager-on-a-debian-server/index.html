Timing closure is a critical part of FPGA design, and verifying that firmware does not violate timing is mandatory if the implementation is to perform as designed. Electrons move at a specific speed, and transistor switching speed is based on physical dimensions as well as internal capacitance. When you write RTL code you are designing hardware, flipping switches and filling Look-Up Tables (LUTs), and even environmental considerations such as temperature and humidity can affect the performance of programmable circuits.

This guide focuses on concerns that arise from implementing a resource-heavy algorithm on hardware where consideration is only given to performance and speed for the algorithm being implemented. It points out common design pitfalls and leaves the designer with several factors to consider as they architecture a complex firmware design.

Background

Lucas-Kanade

Computer vision is algorithm-heavy; it is an ideal field to demonstrate the value of FPGA implementations for logic that is traditionally handled by software. It is also a very broad field, so there are numerous algorithms that can be covered; and a real-world implementation will likely use multiple working in tandem.

One important function of computer vision is simply discerning what the camera is seeing. A camera is essentially taking in a 3-dimensional space and transposing it onto a 2-dimensional image, so how does that image convey depth? It is useful, for both obstacle detection as well as target acquisition, for a vehicle to be able to discern background and foreground objects; applications such as these are perfect for algorithms like Lucas-Kanade.

The Lucas-Kanade (or L-K) handles environmental depth detection by assuming that the flow of an image is essentially constant in a local area of pixels being examined. From the point of view of the observer vehicle, the background image will move much slower than an object in the foreground. It uses this assumption to join similar image flows together and determine individual objects presented to the camera on a 2-dimensional plane, representative of a 3-dimensional space. What this essentially means is that, using the camera data on a moving vehicle, it can pick out a fast-moving foreground item versus a slower moving background item.
